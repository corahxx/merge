# 充电数据清洗与标准化规范 (V2.0)

本规范用于指导对充电站（Station）与充电桩（Pile）原始数据进行全流程清洗，确保护入库数据的单位统一与逻辑严密。

---

## 一、通用清洗规则（全表适用）

### 1.1 基础字段处理

- **空值标准化**：将所有 `null`、`NULL` 或文本 `"null"` 统一替换为空字符串 `""`。
- **序号列**（列名：**序号**）：递增整数列，仅作展示与行号用，**不再作为主键**（充电站表）；充电桩表还会参与 uid 复合（见 1.2）。默认从 **1** 起递增；自定义清洗中可指定**起始值**（如从 10 起则为 10、11、12…）。充电桩表可在自定义清洗中**取消勾选**「序号列」规则：若表中已有有效序号则直接用于 uid；若无数号或序号全空，则在生成 uid 时**自动**按当前设定的起始值补全序号列。
- **主键（uid）**：新增一列作为主键，列名为 **uid**；由若干字段值**复合**后计算**哈希值**得到（见 1.2）。
- **文本限制**：针对「充电站位置」字段，长度超过 600 字符时进行截断（对应 varchar(600)）。
- **映射预留**：预留「运营商名称」映射接口，用于后期通过映射表自动补全运营商全称。

### 1.2 主键（UID）生成规则

- **用途**：UID 为清洗后表的**主键**，用于唯一标识一行；同一行在重复清洗或合并时，相同复合字段应得到相同 UID，便于去重与关联。
- **生成方式**：
  1. **复合字段**：按表类型取下列字段（若某字段不存在则跳过，或按实现约定用空字符串参与拼接）。
  2. **拼接**：将各字段转为字符串，空值用统一占位（如空字符串）；按固定顺序用分隔符（如竖线 `|`）拼接成一条字符串。
  3. **哈希**：对拼接后的字符串计算 **MD5**，取**十六进制**结果作为该行的 UID（如 32 位小写十六进制字符串）。
- **充电站表**：复合字段为 **充电站内部编号**、**充电站名称**（按此顺序，由实现约定并固定）。
- **充电桩表**：复合字段为 **充电桩编号**、**所属充电站编号**、**充电站内部编号**、**序号**（按此顺序，由实现约定并固定）。若表中**已有**非空序号，生成 uid 时直接使用；若无数号列或序号**全为空**，则在生成 uid 前自动按**序号起始值**（默认 1，自定义清洗可填，如 10）生成序号列后再算 uid。勾选「序号列」规则时，会按该起始值**覆盖重写**序号列（建议在需要统一重排序号或与 uid 一并执行时使用）。
- **主键列名**：两表主键列名均为 **uid**。
- **空行处理**：若某行所有参与复合的字段均为空，则 UID 可约定为「序号对应的唯一标识」或「基于行号的哈希」，避免全空导致多行 UID 重复。
- **执行顺序**：UID 生成建议在空值标准化之后、其余清洗规则之前或之后（由实现约定），确保参与复合的字段已标准化后再拼接哈希。充电桩表规则列表中「序号」在「uid」之前，便于一键全选时先写序号再算 uid；自定义清洗可取消「序号」，由 uid 步骤按上条自动补序号。

## 二、日期清洗与监控（核心逻辑）

### 2.1 适用字段

对以下列名进行日期清洗（列名**包含**下列关键词或与下列字段完全匹配即纳入清洗）：

- **固定字段**：【充电站投入使用时间】、【设备开通时间】、【入库时间】、【充电桩生产日期】。
- **通用匹配**：列名包含【时间】或【日期】的字段（凡在库表定义中映射为 `timestamp` / `date` 的列，只要列名符合本规则即逐列处理；具体以实际表结构为准）。
- **排除**：列名为【服务时间】的字段**不**做日期转换，保留原值。
- **排除（勿误伤）**：
  - 列名以 **`_日期清洗结果`** 结尾的列（清洗结果 0/1 标记列）**不参与**本规则，也**不参与** Excel 序列号转换。
  - 列名以 **`_标记`** 或 **`_标志`** 结尾的列视为明显的 0/1 类标记列，**不参与** Excel 序列号转换（避免把单元格里的 0、1 当成日期）。

仅对上述适用字段中的单元格做格式识别与转换；其他列不参与日期清洗。**充电站表与充电桩表均适用。**

### 2.2 支持的源格式（包括但不限于）

| 类型       | 示例 |
|------------|------|
| 中文       | 2023年8月29日 |
| 斜杠       | 2023/3/11、2023/03/11 |
| 紧凑数字   | 20200920；另见 **2.3.1** 对 `yyyyMMdd` 日非法的规整 |
| 标准横杠   | 2021-03-03、2022-11-20 06:02:03（含时分秒的合法 ISO 见 **2.3** 保留规则） |
| 美式格式   | 10 13 2022 12:00AM、12 21 2022 12:00AM |
| Excel 序列号 | 纯数字如 `45138`、`45138.0`（列允许且 `1 < 值 ≤ 100000`，不含 0、1） |

以及缺失「日」仅到月的情况（如 `2025-03`、`2023/8`），缺失日则按 **1 号** 补全。

### 2.3 目标格式与替换规则（PostgreSQL 入库）

- **目标**：凡将入库为 **PostgreSQL `date` / `timestamp`** 的列，单元格最终应为数据库可识别的日期时间文本，例如 **`YYYY-MM-DD`** 或 **`YYYY-MM-DD HH:MM:SS`**；**不得**在应表示时刻的列中保留无意义的**纯数字字符串**（如 `45138`、`45138.0` 等 Excel 序列号原样入库）。
- **已合法文本（不要改）**：若单元格已是 **`YYYY-MM-DD`**、**`YYYY-MM-DD HH:MM:SS`**，或 **`datetime.fromisoformat` 能解析**的 ISO 风格字符串（含 `T` 分隔或空格分隔日期与时间），则**原样保留**（仅可做首尾空白 trim，不改变语义）。
- **Excel 序列号（1900 系统）**：若单元格为**纯数字**（整数或小数，如 `45138`、`45138.0`），且数值落在合理区间 **(1, 100000]**（**不含 0、1**，以免与 0/1 标记混淆），则按与 **Excel / WPS** 一致的 **1900 日期系统**转换：使用 **openpyxl** 等与 Excel 一致的算法，将序列号转为日期时间；**无小数部分**（视为整日）时输出 **`YYYY-MM-DD`**；**含小数部分**（表示日内时间）时输出 **`YYYY-MM-DD HH:MM:SS`**。
- **其它可解析文本**：中文、斜杠、紧凑 `yyyymmdd`、美式等仍按 **2.2** 识别；能解析为日期的，输出 **`yyyy-mm-dd`**（仅日期部分；若源串含合法时分秒且已通过 ISO 保留分支，则不在此条覆盖）。
- **无法解析**：既非合法日期时间文本、又不能作为合理 Excel 序列号转换的**非空**单元格，**置为空字符串** `""`（导出 CSV 时空单元格；若业务需要 `NULL` / `\N`，在入库或 COPY 阶段另行处理）。
- **日=00**：「日期清洗」步骤本身**不**将 `yyyy-mm-00` 改为 `yyyy-mm-01`；需在自定义清洗中勾选 **「日期中00日处理」**（见 2.6）。一键清洗默认在「日期清洗」之后执行该规则。
- 转换后改写原列内容；并实现 **「xxx_日期清洗结果」** 列（见 2.5）。

### 2.3.1 八位 `yyyyMMdd` 紧凑日期（向量化，在「日期清洗」内执行）

- **形态**：单元格为**恰好 8 位数字**的字符串，或数值落在 **`[10^7, 10^8)`** 的**整数**（如 `20220100`、`20220299`；浮点如 `20220100.0` 在可解析为整数时同等对待）。
- **月非法**（`MM` 不在 01–12）：单元格**置空**（便于 PostgreSQL 识别为缺失）。
- **日非法**：`DD=00`，或 `DD` **大于当月实际天数**（如 2 月 99 日、6 月 99 日）：**一律将日改为 `01`**，保留原 `YYYY`、`MM`（**不按月末截断**）。
- **日合法**：规范为 **`YYYY-MM-DD`** 字符串（与原先紧凑格式成功路径一致）。
- **性能**：按**日期列**逐列向量化处理（字符串切片 + `numpy` 日历运算），避免逐行 Python 循环。
- **报告**：`date_yyyymmdd_day_to_01_count`（日改为 01 的单元格数）、`date_yyyymmdd_invalid_month_cleared_count`（非法月置空单元格数）。

### 2.4 转换示例

| 原值 | 转换后 |
|------|--------|
| 2023年8月29日 | 2023-08-29 |
| 2023/3/11 | 2023-03-11 |
| 20200920 | 2020-09-20 |
| 2022-11-20 06:02:03 | 合法 ISO 时**原样保留**（见 2.3）；否则可能仅输出日期部分 |
| 10 13 2022 12:00AM | 2022-10-13 |
| 2025-03 | 2025-03-01 |
| `20220100`、`20220300`、`20220400`、`20220600`（8 位，日为 00） | `2022-01-01`、`2022-03-01` 等（日一律改为 01，见 **2.3.1**） |
| `20220299`、`20220399`、`20220699`（8 位，日超当月天数） | `2022-02-01`、`2022-03-01`、`2022-06-01`（日一律改为 01） |
| `2022-01-00`（横杠形式日=00） | 需勾选「日期中00日处理」后变为 `2022-01-01` |
| `45138`（Excel 序列号，在允许列上） | 转为与 Excel 一致的日历日 `YYYY-MM-DD`（具体日与 openpyxl/Excel 对齐） |
| `2022-11-20 06:02:03`（已合法 ISO 风格） | 原样保留（含时分秒） |
| 原为空 / null | 仍为空；`_日期清洗结果` 记 1 |
| 无法识别且非空 | **置空**；`_日期清洗结果` 记 0 |

### 2.5 清洗监控与报告

- 对每个参与日期清洗的列新增 **xxx_日期清洗结果** 列：**原单元格为空（或等价空）**、或**清洗成功**（含合法文本未改、Excel 序列号已转换、其它规则解析成功）赋 **1**；**原非空且仍无法解析**赋 **0**（此时原列已**置空**）。
- 统计：`date_clean_success`（结果为 1 的单元格数）、`date_clean_fail`（结果为 0 的单元格数）、无法识别样例 `date_unknown_formats`；
- 统计：**Excel 序列号转为日期**的单元格数 `date_excel_serial_converted_count`；
- 统计：**八位 `yyyyMMdd` 日改为 01** `date_yyyymmdd_day_to_01_count`、**八位日期非法月置空** `date_yyyymmdd_invalid_month_cleared_count`（见 **2.3.1**）。

### 2.6 日期中00日处理（自定义规则）

- **名称**：自定义清洗中显示为「日期中00日处理」。
- **适用**：与 **2.1 适用字段** 相同（即 `_get_date_columns` 所确定的列：固定日期字段 + 列名含「时间」「日期」且排除「服务时间」）。
- **规则**：单元格为**严格** `yyyy-mm-00`（10 字符，末两位为 `00`）时，将日改为 `01`，即 `yyyy-mm-01`；其它形态（含带时分秒的字符串、非标准格式）**不**由本规则改写。
- **顺序**：建议在「日期清洗」**之后**执行；充电站表与充电桩表均适用。
- **报告**：统计修正的单元格总数（`date_zero_day_fixed_count`）。

### 2.7 电表号过长处理（自定义规则）

- **名称**：自定义清洗中显示为「电表号过长处理」。
- **适用**：列名**包含**子串「电表号」的**所有列**（如「电表号」「主电表号」等）。
- **规则**：将单元格转为字符串后截断为**最多 50 个字符**，与数据库 `varchar(50)` 等业务上限对齐；不足 50 字的不变。
- **顺序**：与日期无强依赖；实现中紧接在「日期中00日处理」之后、功率等规则之前；充电站表与充电桩表均适用。
- **报告**：统计发生截断的单元格数（`meter_truncated_count`）。

## 三、数值清洗与单位换算规则

**严禁直接删除单位。** 必须根据以下逻辑将变量换算为规定单位。

### 3.1 功率类

| 涉及变量（原始字段名） | 目标单位 | 换算逻辑 |
|------------------------|----------|----------|
| 站点总装机功率、交流/直流桩总装机功率、额定功率 | **kW（千瓦）** | 1. 包含 "W" 但不含 "kW" 时，除以 1000。<br>2. 数值判定：若原始值为纯数字且 > 1000（如 11424），识别为 W，需除以 1000 转换为 11.424。 |

### 3.2 电压类

| 涉及变量 | 目标单位 | 换算逻辑 |
|----------|----------|----------|
| 额定电压上限、额定电压下限 | **V（伏特）** | 1. 包含 "kV" 时，乘以 1000。<br>2. 常见值如 380、220 等直接保留。 |

### 3.3 电流类

| 涉及变量 | 目标单位 | 换算逻辑 |
|----------|----------|----------|
| 额定电流上限、额定电流下限 | **A（安培）** | 1. 剔除 "A" 后保留数字部分。<br>2. 常见值如 158、316 等直接保留。 |

## 四、充电站 (Station) 专项规则

### 4.1 功率对齐

- 对「站点总装机功率」「交流桩总装机功率」「直流桩总装机功率」进行上述 kW 换算，确保全局单位一致。

### 4.2 关键字段校验

- 重点核查「充电站内部编号」。
- 若该字段缺失，需在清洗报告中记录为「异常记录」，因其直接影响站数统计。

## 五、充电桩 (Pile) 专项规则

### 5.1 地理位置（API + 映射）

- **坐标优先**：调用高德 API，根据经纬度反查并填充标准的 **省份_中文、城市_中文、区县_中文**。
- **编码回退**：若无经纬度，则根据省、市、区县编码进行映射（映射表后续补充）。

### 5.2 设备类型标准化（硬性规则）

根据原始字段内容，按以下优先级映射：

- **规则 A**：原始字段不含任何汉字且包含数字 **1** → 清洗为「交流」。
- **规则 B**：原始字段不含任何汉字且包含数字 **2** → 清洗为「直流」。
- **规则 C**：包含其他文字（如「01交流」「02直流分体」「05其他」等）的情况，暂时保持原样，不做清洗。

### 5.3 时间序列校验

- **逻辑检查**：校验「设备开通时间」，必须早于当前系统时间。
- 若时间逻辑异常（如穿越到未来），在清洗报告中标记。

## 八、经纬度字段不合理清洗

勾选「经纬度字段不合理清洗」后执行。针对**经度**、**纬度**两列，保证数值在物理范围内、保留 6 位小数、整数部分不超限，异常值标记为空（NULL/空字符串）。

### 8.1 问题与业务规则

- **问题**：纬度出现异常值（如 3130475.0），超出物理范围（纬度 -90~90，经度 -180~180），且可能超出数据库 numeric(12,6) 整数位上限（整数部分纬度≤3 位、经度≤3 位）。
- **规则**：
  1. **范围校验**：纬度需在 **[-90, 90]**，经度需在 **[-180, 180]**。
  2. **异常处理**：超出范围的数值**直接标记为 NULL**（实现中可为空字符串或 pd.NA）。
  3. **格式**：合法值**保留 6 位小数**（四舍五入），整数部分纬度≤3 位、经度≤3 位（由上述范围自然满足）；若整数部分超限（如 100.123456 的纬度）也标记为 NULL。

### 8.2 清洗步骤

| 步骤 | 说明 |
|------|------|
| 1 | 校验数值范围：纬度 ∈ [-90, 90]，经度 ∈ [-180, 180]。 |
| 2 | 超出范围的异常值直接标记为 NULL。 |
| 3 | 合法值保留 6 位小数（四舍五入），确保整数部分纬度≤3 位、经度≤3 位；否则标记为 NULL。 |

### 8.3 报告要求

- 记录**每类问题的清洗行数**（经度异常行数、纬度异常行数或合计）。
- 记录**异常值示例**（原值）。
- 记录**修正方式**：标记为 NULL。

## 九、联系电话过长审查

勾选「联系电话过长审查」后执行。针对**充电站联系电话**字段，限制为符合实际业务的长度与字符，超长或无意义内容置空。

### 9.1 问题与业务规则

- **问题**：字段存在超长字符串（如连续数字超过 varchar(50)），需清洗为合理长度。
- **规则**：充电站联系电话应为 11 位手机号，或多个手机号用英文逗号分隔，**总长度不超过 50 字符**。

### 9.2 清洗步骤

| 步骤 | 说明 |
|------|------|
| 1 | **过滤非数字字符**：仅保留 0-9 和英文逗号。 |
| 2 | **长度限制**：总长度≤50 字符，超出部分截断。 |
| 3 | **空值/无意义**：空值或无意义字符（如「无」「N/A」等）统一替换为 NULL（实现中可为空字符串）。 |

### 9.3 报告要求

- 记录**清洗行数**（发生截断或置空的行数）。
- 记录**异常值示例**（如超长原值、被置空的原值）。
- 记录**修正方式**：截断至 50 字、仅保留数字与逗号、置空。
